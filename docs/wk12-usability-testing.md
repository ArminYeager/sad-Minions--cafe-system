# รายงานผลการทดสอบ Usability (Usability Testing Report)
## สัปดาห์ที่ 12: การทดสอบความยากง่ายในการใช้งานด้วย Task-Based Testing และ Think-Aloud Protocol

**กลุ่มที่ 14:** Minions Cafe  
**ระบบที่ทดสอบ:** ระบบร้าน Minions Cafe POS Prototype (UI จริงที่เชื่อมโยงระบบ)  
**วันที่ดำเนินการทดสอบ:** 20 ตุลาคม 2568  
**ผู้สังเกตการณ์ (Observer):** กลุ่ม 14 Minions Cafe  
**ผู้เข้าร่วมการทดสอบ (Participant):** ตัวแทนผู้ใช้งานจากกลุ่มคู่ทดสอบ (ผู้สวมบทบาทพนักงานแคชเชียร์และเจ้าของร้านที่ไม่เคยใช้งานระบบมาก่อน)

---

## 1. วัตถุประสงค์ของการทดสอบ (Objectives)

1. ตรวจสอบว่าพนักงานร้านสามารถรับออเดอร์ คำนวณเงิน และออกใบเสร็จได้สำเร็จอย่างราบรื่นหรือไม่
2. ตรวจสอบการรับรู้และการป้องกันความผิดพลาด (Error Prevention) เมื่อสินค้าในสต็อกหมด หรือสั่งซื้อเกินจำนวนสต็อก
3. ประเมินความชัดเจนของตำแหน่ง Branch Selector, ปุ่มยืนยันออเดอร์, และการแสดงผลรายงานยอดขาย
4. บันทึกปัญหาการใช้งาน (Usability Issues) จัดลำดับความรุนแรง (Severity) และนำไปปรับปรุง UI จริงก่อนส่งมอบ

---

## 2. การออกแบบ Task สำหรับการทดสอบ (Task Scenarios)

Task ได้รับการออกแบบตามหลักการใน `wk12.md` โดยกำหนดเป็น **เป้าหมายปลายทาง (Goal-oriented)** โดยไม่ชี้นำขั้นตอนการกดปุ่ม:

### Task 1 (Happy Path - POS Order):
> *"มีลูกค้าต้องการสั่งเครื่องดื่มที่สาขา 1 เป็น Latte จำนวน 1 แก้ว และชำระเงินด้วยเงินสด ขอให้คุณรับออเดอร์และออกใบเสร็จให้ลูกค้า"*

### Task 2 (Error Path - Out of Stock & Validation):
> *"ลูกค้าต้องการสั่ง Espresso เพิ่มอีก 15 แก้วที่สาขา 1 (ซึ่งระบบมีสต็อกเหลือเพียง 8 แก้ว) ให้ลองเพิ่มรายการนี้ในออเดอร์และสังเกตผลตอบรับของระบบ"*

### Task 3 (Reporting - Sales Summary):
> *"เจ้าของร้านต้องการตรวจสอบว่าหลังจากปิดการขายออเดอร์เมื่อสักครู่ ยอดขายรวมของสาขา 1 เป็นเท่าใด และเมนูใดขายดีที่สุด"*

## 4. รายการ Usability Issues และการจัดลำดับความรุนแรง (Severity Rating)

ตามเกณฑ์การประเมินของ Nielsen (Critical, Major, Minor, Cosmetic):

| รหัส | ปัญหาที่พบ (Usability Issue) | ผลกระทบต่อผู้ใช้ | ระดับความรุนแรง (Severity) |
|---|---|---|:---:|
| **UI-01** | **ปุ่ม "ยืนยันออเดอร์" ไม่เด่นชัดพอ:** ในเวอร์ชันเดิมปุ่มยืนยันใช้สีเทาเข้มกลืนกับกล่องตะกร้า ทำให้ผู้ใช้ใหม่ใช้เวลากวาดสายตามองหา | ผู้ใช้ชะงักและใช้เวลาเพิ่มขึ้นในการปิดการขายหน้าร้าน | **Major** |
| **UI-02** | **ปุ่มเมนูที่สต็อกหมด (Stock = 0) ยังกดได้:** เดิมเมนูที่สต็อกเป็น 0 ยังแสดงปุ่มให้กดเพิ่มได้ และเพิ่งแจ้งเตือน Error เมื่อกดยืนยันออเดอร์ | ผู้ใช้สับสนและเสียเวลาเลือกสินค้าที่ไม่มีของ | **Critical** |
| **UI-03** | **ขาดการแสดงยอดเงินทอนอัตโนมัติในใบเสร็จ:** เมื่อเลือกชำระเงินสด ผู้ใช้ต้องการช่องใส่จำนวนเงินที่รับมาและคำนวณเงินทอนอัตโนมัติ | พนักงานต้องคิดเลขในใจหรือใช้เครื่องคิดเลขแยก | **Minor** |
| **UI-04** | **ตัวเลือกสาขา (Branch Selector) ขนาดตัวอักษรเล็กเกินไป:** ในหน้าจอมือถือ/แท็บเล็ตขนาดเล็ก มองเห็นชื่อสาขาไม่ชัดเจน | อาจทำให้พนักงานสลับสาขาผิดพลาด | **Minor** |

## 5. การแก้ไขปัญหาจริงบนระบบ (Implemented Fixes & Refinement)

ทีมงานได้ดำเนินการแก้ไขปัญหาในระบบจริงเรียบร้อยแล้ว ดังนี้:

1. **แก้ไข UI-02 (Critical - Stock 0 Prevention):**
   - **การแก้ไข:** ปรับปรุงโค้ด UI ให้ตรวจสอบ `stock_quantity === 0` หากสินค้าหมด จะเปลี่ยนสีการ์ดเป็นสีเทา ขึ้นป้ายกำกับ **"สินค้าหมด (Out of Stock)"** และ Disable ปุ่มเพิ่มลงตะกร้าทันที พร้อมทั้งย้อนกลับไปบันทึกเป็นข้อกำหนด **FR-11** ใน `wk03-requirements.md`
2. **แก้ไข UI-01 (Major - CTA Visibility):**
   - **การแก้ไข:** ออกแบบปุ่ม "ยืนยันออเดอร์" ใหม่ โดยใช้สีเขียวสดใส (Emerald Accent) เพิ่มขนาดตัวอักษรเป็น Bold มีเงาและ Micro-interaction เมื่อเมาส์ชี้ เพื่อให้เป็น Primary Action ที่ชัดเจนที่สุดในส่วนตะกร้าสินค้า
3. **แก้ไข UI-03 (Minor - Cash Change Calculation):**
   - **การแก้ไข:** เพิ่มช่องกรอก "รับเงินสดมา (Cash Received)" พร้อมคำนวณ "เงินทอน (Change Due)" แสดงผลสดแบบทันที และพิมพ์ยอดเงินที่รับพร้อมเงินทอนลงในใบเสร็จ
4. **แก้ไข UI-04 (Minor - Branch Selector Styling):**
   - **การแก้ไข:** ปรับแต่ง Dropdown เลือกสาขาให้มีสไตล์ชัดเจน มี Badge แสดงชื่อสาขา และคงตำแหน่งมุมบนขวาในทุกหน้าจออย่างคงเส้นคงวา (Consistency)

## 6. สรุปผลการทดสอบและการสะท้อนการเรียนรู้

การทดสอบ Usability Testing ในครั้งนี้พิสูจน์ให้เห็นอย่างเป็นรูปธรรมว่า **"การออกแบบตามหลักการเพียงอย่างเดียวไม่ได้รับประกันว่าผู้ใช้จริงจะใช้งานได้ราบรื่นเสมอไป"** การนำระบบ prototype จริงมาให้ผู้ใช้นอกทีมทดสอบด้วยโจทย์สถานการณ์จริง (Task-Based) ทำให้ทีมค้นพบปัญหาเรื่องเมนูสต็อกหมดและจุดบกพร่องของปุ่มยืนยันออเดอร์ ซึ่งการแก้ไขปัญหาเหล่านี้ก่อนส่งมอบช่วยยกระดับคุณภาพของระบบ Minions Cafe ให้ตรงกับความต้องการและพร้อมใช้งานจริงในสภาพแวดล้อมร้านกาแฟ
